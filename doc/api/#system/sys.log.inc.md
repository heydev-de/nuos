## log_report_option

The `log_report_option` class defines display and behavior options for individual columns in a log report table generated by the `log_report()` function. It allows customization of column names, rendering types (text, beam/bar visualization), link generation, and value transformation via callbacks.

### Properties

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$name` | string\|NULL | NULL | Custom display name for the column header |
| `$type` | int\|NULL | NULL | Rendering type: `CMS_LOG_REPORT_OPTION_TYPE_NONE`, `CMS_LOG_REPORT_OPTION_TYPE_TEXT`, or `CMS_LOG_REPORT_OPTION_TYPE_BEAM` |
| `$link` | string\|NULL | NULL | sprintf-style format string for generating hyperlinks from the column value |
| `$link_encoding` | callable\|NULL | NULL | Callback to encode the link source value before substitution into `$link` |
| `$link_source` | string\|NULL | NULL | Name of another column whose value is used as the link source |
| `$value_function` | callable\|NULL | NULL | Callback to transform the raw cell value before display |

### __construct

Initializes a new `log_report_option` instance with the specified configuration.

#### Parameters

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$name` | string\|NULL | NULL | Custom display name for the column |
| `$type` | int\|NULL | NULL | Rendering type constant |
| `$link` | string\|NULL | NULL | Link format string |
| `$link_encoding` | callable\|NULL | NULL | Link encoding callback |
| `$link_source` | string\|NULL | NULL | Source column name for links |
| `$value_function` | callable\|NULL | NULL | Value transformation callback |

#### Example

```php
$option = new log_report_option(
    name: "User Profile",
    type: CMS_LOG_REPORT_OPTION_TYPE_TEXT,
    link: "https://example.com/user/%s",
    link_encoding: "rawurlencode",
    link_source: "userid"
);
```

This creates an option that renders a column named "User Profile" as a text link pointing to a user profile page, using the `userid` column value as the link parameter.

## log_report

Executes a SQL query and renders the results as an HTML table with optional column-level formatting, linking, and bar visualizations.

### Parameters

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$sql` | string | — | SQL query to execute |
| `$options` | array\|NULL | NULL | Associative array mapping column names to either display names (strings) or `log_report_option` instances |

### Return Values

| Type | Description |
|------|-------------|
| `FALSE` | Query execution failed |
| `array` | When `$options === FALSE`, returns raw result rows as an array |
| `int` | Number of rows returned when rendering a table |
| `TRUE` | Query succeeded but returned no rows |

### Inner Mechanisms

1. **Query Execution**: Runs the SQL query and measures execution time.
2. **Non-SELECT Handling**: For non-SELECT queries (INSERT/UPDATE/DELETE), outputs affected row count and execution time.
3. **Raw Result Mode**: When `$options` is explicitly `FALSE`, fetches all rows into an array and returns them.
4. **Table Rendering**:
   - Builds table headers with optional custom column names.
   - Processes `log_report_option` instances to determine column types (text, beam).
   - For beam columns, performs a two-pass approach: first pass calculates maximum values and sums, second pass renders bars with proportional widths.
   - Supports link generation using sprintf format strings with configurable encoding.
   - Applies value transformation callbacks when provided.
5. **Footer**: For beam-enabled tables, displays summary row with totals.

### Usage Example

```php
$sql = "SELECT user, action, COUNT(*) as hits FROM cms_log_access GROUP BY user, action ORDER BY hits DESC";
$options = [
    "user" => new log_report_option(
        name: "User",
        type: CMS_LOG_REPORT_OPTION_TYPE_TEXT,
        link: "/admin/user/%s",
        link_source: "user"
    ),
    "hits" => new log_report_option(
        name: "Hits",
        type: CMS_LOG_REPORT_OPTION_TYPE_BEAM
    )
];
log_report($sql, $options);
```

This renders a table showing user actions with clickable user names and bar visualizations for hit counts.

## log

The `log` class manages access logging, user tracking, bot detection, and log data cleanup. It interfaces with three database tables: `log_access`, `log_user`, and `log_ua_freq`.

### Constants

| Name | Value | Description |
|------|-------|-------------|
| `CMS_LOG_PERMISSION_OPERATOR` | `"operator"` | Permission level required for log operators |
| `CMS_LOG_STATUS_USER_FIXED` | -1 | User status: fixed (manually classified) |
| `CMS_LOG_STATUS_USER_PROVISIONAL` | 0 | User status: provisional (not yet classified) |
| `CMS_LOG_STATUS_BOT_PROVISIONAL` | 1 | Bot status: provisional |
| `CMS_LOG_STATUS_BOT_LIMIT_EXCEEDED` | 2 | Bot status: exceeded access rate limit |
| `CMS_LOG_STATUS_BOT_FIXED` | 3 | Bot status: fixed (manually classified) |
| `CMS_LOG_STATUS_BAD_BOT` | 4 | Bot status: confirmed bad bot |

### Properties

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$limit` | int\|NULL | NULL | Retention period in days for access logs |
| `$anonymize` | bool\|NULL | NULL | Whether to anonymize IP addresses |
| `$privacy` | bool\|NULL | NULL | Whether to apply privacy measures to user data |
| `$bot_limit` | int | 5 | Maximum accesses within 10 seconds before bot classification |
| `$bad_bot_limit` | int | 10 | Maximum error accesses within 10 seconds before bad bot classification |
| `$bad_bot_delay` | int | 5 | Delay in seconds before bad bot status expires |
| `$bad_bot_block` | bool | FALSE | Whether to block bad bots |
| `$bot_reset` | int | 14 | Days of inactivity before resetting provisional statuses |
| `$bot_retention` | int | 30 | Retention period in days for bot access entries |
| `$operator` | bool | FALSE | Whether current user has operator permissions |
| `$enabled` | bool\|NULL | NULL | Whether logging is enabled |

### __construct

Initializes the log system by verifying database tables and loading configuration values.

#### Inner Mechanisms

1. Creates a `mysql` instance and verifies existence of `log_access`, `log_user`, `log_ua_list`, and `log_ua_freq` tables.
2. If all tables exist, loads configuration from the system settings:
   - Log retention limit
   - Anonymization and privacy flags
   - Bot detection thresholds
   - Bad bot blocking settings
3. Sets `$enabled` to `TRUE` if initialization succeeds.

### access

Logs an access event with detailed client information and performs bot detection.

#### Parameters

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$action` | string\|NULL | NULL | Action identifier (e.g., "page_view", "login") |
| `$info` | string\|NULL | NULL | Additional information about the access |

#### Inner Mechanisms

1. **Rate Limiting Check**: Queries recent accesses (last 10 seconds) to detect repeated identical requests.
2. **Bot Detection**:
   - Retrieves current bot status from `log_user` table.
   - If access rate exceeds `$bot_limit`, escalates to `CMS_LOG_STATUS_BOT_LIMIT_EXCEEDED`.
   - If error rate exceeds `$bad_bot_limit`, escalates to `CMS_LOG_STATUS_BAD_BOT`.
3. **Data Collection**:
   - Gathers user info, IP address, URL, referrer, user agent, browser, mobile flag, language, and region.
   - Parses `Accept-Language` header to extract primary language and region.
4. **Database Insert**: Writes a record to `log_access` table.
5. **Bad Bot Blocking**: If enabled and user is a confirmed bad bot, terminates the request.

#### Usage Example

```php
$log = new log();
$log->access("page_view", "Homepage");
```

This logs a page view access event with the action "page_view" and info "Homepage".

### user

Creates or updates a user record in the log system, managing bot status transitions.

#### Parameters

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$name` | string\|NULL | NULL | User name or pseudonym |
| `$email` | string\|NULL | NULL | User email address |
| `$info` | string\|NULL | NULL | Additional user information |
| `$bot` | int\|NULL | NULL | Bot status constant |
| `$userid` | string\|NULL | NULL | User identifier (defaults to `CMS_IPHASH`) |
| `$append` | bool | TRUE | Whether to append to existing values rather than replace |

#### Inner Mechanisms

1. **Privacy Handling**: When `$privacy` is enabled, preserves existing names/emails or generates pseudonyms.
2. **Append Mode**: When `$append` is `TRUE`, merges new values with existing ones (up to 3 entries).
3. **Bot Status Transition**:
   - Detects when bot status changes from provisional to confirmed.
   - Updates `bot_time` when status changes.
   - Retroactively updates `log_access` records when user/bot classification changes.
4. **Database Operation**: Uses `INSERT ... ON DUPLICATE KEY UPDATE` for atomic upsert.

#### Usage Example

```php
$log = new log();
$log->user("John Doe", "john@example.com", "Registered user", CMS_LOG_STATUS_USER_FIXED);
```

This creates or updates a user record with the name "John Doe", email "john@example.com", and fixed user status.

### set_user

Convenience wrapper for `user()` that forces replacement mode (`$append = FALSE`).

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `$userid` | string | User identifier |
| `$name` | string | User name |
| `$email` | string | User email |
| `$info` | string | Additional info |
| `$bot` | int | Bot status |

#### Usage Example

```php
$log = new log();
$log->set_user(CMS_IPHASH, "Jane Smith", "jane@example.com", "Admin user", CMS_LOG_STATUS_USER_FIXED);
```

This sets user data in replacement mode, overwriting any existing values.

### cleanup

Removes old log entries and resets provisional bot statuses.

#### Inner Mechanisms

1. **Bot Access Cleanup**: Deletes bot access entries older than `$bot_retention` days.
2. **General Access Cleanup**: Deletes access entries older than `$limit` days.
3. **Orphaned User Cleanup**: Removes user records with no associated access entries and provisional statuses.
4. **Status Reset**: Resets provisional bot statuses for users inactive for more than `$bot_reset` days.

#### Usage Example

```php
$log = new log();
$log->cleanup();
```

This should be called periodically (e.g., via cron) to maintain log table sizes.

### browser

Analyzes a user agent string to determine browser identification.

#### Parameters

| Name | Type | Default | Description |
|------|------|---------|-------------|
| `$string` | string | — | User agent string |
| `$count` | int | 1 | Number of lowest-frequency tokens to include |

#### Return Values

| Type | Description |
|------|-------------|
| string | Browser identification string (e.g., "Chrome-Mobile") |

#### Inner Mechanisms

1. **Tokenization**: Parses the user agent string into tokens (browser names, versions).
2. **Frequency Tracking**: Queries and updates token frequency counts in `log_ua_freq` table.
3. **Token Selection**: Selects the `$count` lowest-frequency tokens to form a unique identifier.
4. **Mobile Detection**: Appends "Mobile" token if detected in the user agent.

#### Usage Example

```php
$log = new log();
$browser = $log->browser($_SERVER["HTTP_USER_AGENT"]);
echo "Detected browser: " . $browser;
```

This identifies the browser from the user agent string and outputs the result.
